# 12 周迭代计划（首发版）

## 1. 计划原则
1. 每个 Sprint 为 2 周，共 6 个 Sprint。
2. 先打基础，再完成四科闭环，再做模考和商业化，最后做发布收口。
3. 所有 Sprint 均包含开发、测试和修复缓冲。

## 2. Sprint 排期总览
| Sprint | 周期 | 目标 | 主要 Story | 出口标准 |
|---|---|---|---|---|
| S1 | W1-W2 | 平台基础与账号打通 | US-1101, US-1102, US-2101 | 登录稳定，目标设置可用，核心 API 可联调 |
| S2 | W3-W4 | 同步、诊断、基础计划 | US-1103, US-1104, US-2102, US-2103 | 诊断 <= 5 分钟，8 周计划可生成 |
| S3 | W5-W6 | 听力/阅读核心闭环 + 口语会话基础 | US-3101, US-3102, US-3103, US-5101, US-5102, US-4101 | 听读训练可用，口语实时会话稳定 |
| S4 | W7-W8 | 口语评分、写作批改、模式完善 | US-4102, US-4103, US-4104, US-5103, US-6101, US-6102 | 口语四维评分达标，写作反馈 <= 90 秒 |
| S5 | W9-W10 | 模考、计划回写、订阅权益 + 后台基础 | US-6103, US-7101, US-7102, US-7103, US-8101, US-8102, US-8103, US-11101, US-11103 | 模考报告 <= 2 分钟，权益逻辑跨端一致，后台登录与订单校正可用 |
| S6 | W11-W12 | 可观测性、回归、门禁与发布 + 后台收口 | US-9101, US-9102, US-10101, US-10102, US-11102, US-11104 | 发布门禁通过，灰度和回滚可执行，后台用户与内容管理可用 |

## 3. Sprint 详细交付
### S1（W1-W2）
1. 交付范围:
- 注册登录、会话刷新、目标设置。
2. 风险:
- 登录方式接入第三方认证可能影响进度。
3. 缓解:
- 先实现邮箱和手机号，第三方登录采用特性开关。

### S2（W3-W4）
1. 交付范围:
- 云同步、账号注销、首次诊断、8 周计划生成。
2. 风险:
- 诊断题库与评分策略尚需迭代。
3. 缓解:
- 先上线最小题量与规则评分，再接 AI 校准。

### S3（W5-W6）
1. 交付范围:
- 听力和阅读题型引擎、错因反馈、口语实时会话骨架。
2. 风险:
- 多端音频能力差异导致会话质量不一致。
3. 缓解:
- 提前做平台兼容测试和兜底降级策略。

### S4（W7-W8）
1. 交付范围:
- 口语追问与四维评分、写作评分与建议、阅读考试模式。
2. 风险:
- AI 输出质量不稳定影响体验。
3. 缓解:
- 使用评测集做日常回归，并启用备模型回退。

### S5（W9-W10）
1. 交付范围:
- 模考流程、报告生成、计划回写、订阅支付与权益同步、后台登录与订单校正。
2. 风险:
- 支付链路和权益系统联动复杂。
3. 缓解:
- 增加沙箱支付回归脚本和多端对账校验。

### S6（W11-W12）
1. 交付范围:
- 数据埋点、告警、四端回归、发布门禁、灰度和回滚流程、后台用户与内容管理收口。
2. 风险:
- 回归范围大导致修复压力集中。
3. 缓解:
- 前置自动化用例，保留至少 20% 修复缓冲。

## 4. 发布门禁（S6 末）
1. P0 缺陷为 0。
2. 四端 P0 场景通过率 >= 98%。
3. API 成功率 >= 99.5%。
4. AI 首 token P95 <= 3 秒。
5. 模考报告生成 P95 <= 120 秒。
6. 订阅与权益一致性通过全量回归。

## 5. 角色与节奏建议
1. 每周一: Sprint 计划和风险梳理。
2. 每周三: 跨端联调与 AI 质量巡检。
3. 每周五: 回归报告和下周风险预警。
4. 每 Sprint 结束: 演示、复盘、验收签署。

## 6. 变更策略
1. 新增需求默认进入 P1 池，除非影响首发核心目标。
2. 若出现 P0 线上风险，允许中断当前 Sprint 优先修复。
