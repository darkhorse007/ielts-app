# 删除例外与处理时效草案（Draft for Review）

## 文档信息
- 版本: v0.1
- 状态: Draft for Review
- 创建日期: 2026-03-14
- 适用范围: 当前 `IELTS AI App` 账号删除、数据导出与日志留存口径
- 说明: 本文用于将“删除能力已实现”推进到“对外说明、例外边界与内部处理时效可签署”。未签署前不得直接对外发布。

## 1. 目的
1. 明确用户自助删除、用户数据导出与删除例外的当前实际行为。
2. 区分“立即从在线主存储清理”与“因法定/审计/备份原因不能即时逐份删除”的数据类别。
3. 为隐私政策、用户协议、客服话术和法务签署提供统一底稿。

## 2. 当前代码事实
1. 用户可通过 `GET /v1/users/me/export` 立即下载当前账户范围内的 JSON 数据副本。
2. 用户可通过 `POST /v1/users/me/deletion-request` 发起删除请求。
3. 用户可通过 `POST /v1/users/me/delete` 并提交 `confirm_text=DELETE` 立即触发在线主存储删除流程。
4. 删除动作会撤销会话，清理目标、计划、练习、口语、写作、模考、权益、订单事件、提醒与部分分析相关数据。
5. 删除动作会追加 `deletion_requested`、`user_deleted`，数据导出会追加 `user_data_exported` 审计。

## 4. 删除例外矩阵
| data category | example | why exception exists | current handling baseline | publish wording draft | owner |
|---|---|---|---|---|---|
| 审计日志 | admin audit、下载审计、风控审计 | 安全追责、合规、争议处理 | 不随普通删号即时删除 | “为保障安全、追责与合规，必要审计记录可能依法保留。” | legal + security + ops |
| 支付与退款记录 | order、provider order id、退款状态 | 财务对账、退款争议、法定义务 | 不应承诺随普通删号即时清空 | “支付与退款记录可能因财务和法律义务保留。” | finance + legal |
| 安全日志 | 登录失败、异常设备、黑名单 | 安全分析、欺诈识别 | 保留用于安全审查 | “为防止滥用与保障账号安全，部分安全日志会按合法目的保留。” | security |
| 分析数据 | analytics events、cohort evidence | 统计、留存分析、运营复盘 | 当前部分数据仍需进一步去标识与保留规则联签 | “统计分析信息会按最小化和必要原则保留，并逐步去标识化。” | product + legal + data |
| 备份 / PITR | snapshot、backup artifact | 容灾恢复 | 不支持逐份即时删除，只能按备份生命周期自然出清 | “已写入备份的数据不会即时逐份删除，会在备份周期结束后自然出清。” | ops + legal |

## 5. 当前禁止承诺
1. 不承诺“删号后所有日志即时全部删除”。
2. 不承诺“备份中的数据可即时逐份删除”。
3. 不承诺“客服可以代用户定向删除部分支付/审计记录”。
4. 不承诺“导出副本包含后台审计、内部风控或第三方平台原始账务明细”。

## 6. 对外文案建议
### 6.1 短版
1. “你可以下载自己的数据副本，也可以发起账号删除。出于财务、安全、审计和备份恢复需要，部分记录可能在合法范围内保留一段时间。”

### 6.2 长版
1. “当你确认删除账号后，我们会从在线主存储中清理与你学习和账号使用直接相关的数据，并撤销现有会话。为履行法律义务、处理退款争议、保障安全和容灾恢复，部分支付、审计、安全日志及备份中的记录可能不会即时逐份删除，而会按照适用规则继续保留一段时间或在备份周期结束后自然出清。”

## 7. 待签署项目
1. 分析数据的最终 retention 与是否必须去标识化。
2. 审计日志、安全日志、支付记录各自的对外保留期限表述。
3. 备份生命周期与“自然出清窗口”。
4. 客服是否可以代用户触发导出，以及需要的鉴权校验。
