# PRD 附录 B: 测试计划与发布验收标准

## 文档信息
- 文档版本: v1.0
- 关联文档: `docs/PRD-IELTS-AI-App.md`, `docs/PRD-Appendix-IA-Data-API.md`
- 创建日期: 2026-02-25

## 1. 测试目标
1. 验证产品是否满足“雅思过关导向”的核心业务目标。
2. 验证四端功能一致性与稳定性。
3. 验证 AI 反馈质量、可解释性与可执行性。
4. 验证订阅与权益链路准确性。
5. 验证性能、安全、合规是否达标。
6. 验证后台管理系统的权限隔离与操作可追溯性。

## 2. 测试范围
### 2.1 In Scope
1. 账号、诊断、学习计划、四科训练、模考、复盘、订阅。
2. AI Agent 路由、回退、输出质量。
3. 跨平台兼容性（iOS/Android/Windows/macOS）。
4. 核心 API 与实时会话链路。
5. 后台管理端（Admin Web）的用户、订单、内容、审计能力。

### 2.2 Out of Scope
1. 机构版后台能力。
2. 真人教练服务。

## 3. 测试环境矩阵
1. iOS: 最近 2 个主版本系统。
2. Android: 最近 4 个主版本系统，覆盖中端和高端机。
3. Windows: Windows 10/11。
4. macOS: 最近 2 个主版本。
5. 网络条件: Wi-Fi、4G/5G、弱网（高延迟 + 丢包）。
6. Admin 浏览器: Chrome 最新版、Edge 最新版。

## 4. 测试类型与通过标准
### 4.1 功能测试
通过标准:
1. P0 功能测试用例通过率 100%。
2. P1 功能测试用例通过率 >= 95%。

### 4.2 接口测试
通过标准:
1. 核心 API 成功率 >= 99.5%（压测环境）。
2. 错误码与异常语义符合接口文档定义。

### 4.3 AI 质量测试
通过标准:
1. 口语反馈覆盖四维评分且提供可执行建议的比例 >= 98%。
2. 写作反馈包含评分、证据句、修改建议的比例 >= 98%。
3. 模型回退场景下服务可用率 >= 99%。

### 4.4 性能测试
通过标准:
1. 常规 API P95 延迟 <= 1.5 秒。
2. AI 首 token P95 <= 3 秒。
3. 模考报告生成 P95 <= 120 秒。

### 4.5 稳定性测试
通过标准:
1. 客户端崩溃率 <= 0.3%。
2. 核心链路 24 小时 soak test 无 P0 阻断缺陷。

### 4.6 安全与合规测试
通过标准:
1. 鉴权绕过、越权访问、明文敏感信息泄露均为 0。
2. 隐私协议、注销流程、数据删除链路全部可执行。
3. 题库版权来源证明完整可追踪。

## 5. 核心验收场景（必须通过）
### 5.1 用户入门闭环
1. 新用户注册。
2. 完成目标设置和首次诊断。
3. 获取 8 周计划并完成首个任务。

验收阈值:
1. 全流程耗时 <= 5 分钟。
2. 无阻断错误。

### 5.2 口语即时对练闭环
1. 发起 Part 2 对练并上传语音。
2. 获得追问、分项评分、证据句和建议。
3. 触发“再答一次”并展示前后对比。

验收阈值:
1. 首次反馈首条内容 <= 3 秒。
2. 四维评分齐全且每维有解释。

### 5.3 写作批改闭环
1. 提交 Task 2 文章。
2. 获取 TR/CC/LR/GRA 评分。
3. 执行改写并复评。

验收阈值:
1. 单次反馈 <= 90 秒。
2. 至少输出 3 条可执行修改建议。

### 5.4 模考与计划更新闭环
1. 完成一次全真模考。
2. 获取复盘报告。
3. 自动更新下一周计划。

验收阈值:
1. 报告生成 <= 2 分钟。
2. 计划更新动作可追踪且有理由说明。

### 5.5 订阅权益闭环
1. 开启试用。
2. 升级订阅。
3. 取消续费并等待到期降级。

验收阈值:
1. 权益状态切换准确，生效延迟 <= 1 分钟。
2. 各端展示一致。

### 5.6 后台管理闭环
1. Admin 登录并按角色进入后台。
2. 查询用户并执行冻结/解冻操作。
3. 查询订单并执行一次权益人工校正。
4. 发布一个题库内容版本并核验审计日志。

验收阈值:
1. 越权操作拦截率 100%，返回 `403`。
2. 冻结/解冻在 1 分钟内影响前台访问状态。
3. 每次高风险操作均可在审计日志检索到完整记录。

## 6. 跨平台一致性测试清单
1. 同一账号多端登录后学习进度一致。
2. 同一训练会话反馈结构一致。
3. 模考计时逻辑一致。
4. 权益判断逻辑一致。
5. 弱网与断网恢复策略一致。

## 7. AI Agent 专项测试
### 7.1 路由测试
1. 主模型可用时默认命中主路由。
2. 主模型超时时 10 秒内切换备路由。
3. 回退后结果结构保持不变。

### 7.2 质量测试
1. 对固定评测集执行口语和写作批改。
2. 检查反馈是否包含证据与建议。
3. 检查是否出现无关或不可执行建议。

### 7.3 安全测试
1. 提示注入对抗测试。
2. 敏感话题输出约束测试。
3. 恶意输入鲁棒性测试。

## 8. 缺陷分级与发布门禁
### 8.1 缺陷分级
1. P0: 阻断核心路径或导致数据错误。
2. P1: 关键功能受损但有替代路径。
3. P2: 体验问题或边缘异常。

### 8.2 发布门禁
1. P0 缺陷必须为 0。
2. P1 未关闭数量 <= 3 且需有明确修复计划。
3. 性能、安全、合规项必须全部通过。
4. 四端回归测试通过率 >= 98%。
5. Admin 权限与审计链路测试通过率 100%。

## 9. 上线后监控与回滚策略
1. 监控指标:
- 请求成功率
- AI 回退触发率
- 客户端崩溃率
- 订阅扣费失败率
2. 告警阈值:
- 核心 API 成功率 < 99%
- AI 回退触发率 > 20%
- 崩溃率 > 0.3%
3. 回滚策略:
- 服务端按版本灰度回滚。
- 客户端通过远程配置关闭高风险功能开关。

## 10. 验收签署清单
1. 产品签署: 功能范围与体验目标符合 PRD。
2. 研发签署: 接口、链路、错误处理达标。
3. 测试签署: 用例通过与缺陷状态达标。
4. 法务签署: 隐私、协议、版权合规达标。
5. 运营签署: 试用、订阅、通知链路可执行。

## 11. 默认假设
1. 评测数据集由内部构建并持续扩充。
2. 语音转写服务在目标区域可稳定访问。
3. 商业 LLM Provider 至少存在 2 个可用选项。
4. Admin 后台由内部运营人员使用，不对终端用户开放。
