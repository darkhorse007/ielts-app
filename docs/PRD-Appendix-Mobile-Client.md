- 版本: v1.8
- 状态: Approved Scope + Core Coverage
- 适用分支: `self-hosted`
- 说明: 本附录基于当前 Web 学习端能力，定义 iOS 与 Android 原生移动客户端范围。当前仓库已包含 `apps/mobile` 初始骨架、首日学习链路、听力/阅读训练、实时口语、写作批改、模考与报告，以及账户中心接入，核心学习与账户域已建立移动端入口。

2. 当前已落实例配置、安全会话存储、注册/登录、首页工作台、入门目标、首次诊断、学习计划、学习进度、听力训练、阅读训练、实时口语、写作批改、模考与报告、账户中心、提醒偏好、学习时长提醒、未成年人首次监护提示、未成年人监护留痕、未成年人专门学习时长控制、数据导出、删除账号，以及 API/WS 连接 smoke。

4. 当前 Web 学习主链路与账户主链路已在移动端建立对应入口。
5. 本附录的其余条目仍然代表移动端完整目标范围，而不是“需要另起一轮功能补洞”的清单。

## 1. 目标与边界
1. 交付 iOS 与 Android 学习端，服务于 IELTS 备考核心链路。
2. 移动端以当前 Web 学习端为功能基线，复用同一套 API 与 WebSocket 契约。
3. 移动端面向学习者，不包含支付、订阅、Admin、运营后台或独立移动专用后端。
4. 移动端必须适配自托管部署模式，允许部署方指定 API 与 WebSocket 目标地址。

## 3. 移动端专项要求
### 3.1 账号与安全
1. access token、refresh token、实例配置等敏感数据必须保存在安全存储。
2. 切换自托管实例时，应用必须清空旧实例会话，避免 token 与缓存串用。
3. 退出登录、删除账号、鉴权失效后，移动端必须清除本地敏感数据。

### 3.2 生命周期与恢复
1. 应用从前台切到后台再恢复时，必须重新校验会话与关键学习状态。
2. 诊断、听力、阅读、实时口语、模考场景必须支持中断后恢复。
3. 本地缓存只用于体验恢复，服务端状态为最终事实源。

### 3.3 设备能力
1. 实时口语必须按需申请麦克风权限。
2. 听力与口语必须对来电、系统音频打断、耳机切换、网络抖动提供可理解的提示。
3. 报告导出必须接入系统分享或系统打开能力。

### 3.4 自托管接入
1. 部署方可以在构建时预置 API/WS 地址。
2. 受控场景下，移动端应支持运行时录入或切换自托管实例地址。
3. 若服务端地址不可达，应用必须提供明确错误提示与重试路径。

### 3.5 数据与分析
1. 分析事件需带上 `ios` 或 `android` 平台标识。
2. 提醒偏好、提醒推荐、点击反馈必须延续现有服务端语义。
3. 不新增移动端独有数据模型作为主链路前置条件。

## 4. 明确不做
1. 不开发支付、订阅、会员与订单能力。
2. 不开发 Admin、审核、内容运营后台。
3. 不开发桌面端、Pad 专项排版版本、手表端、TV 端。
4. 不以首期移动端为前提引入完全离线题库与离线判分。
5. 不要求与 Web 逐像素一致。

## 5. 验收口径
1. iOS 与 Android 端都必须能完成注册/登录 -> 入门目标 -> 诊断 -> 计划查看的首日流程。
2. iOS 与 Android 端都必须能完成听力、阅读、实时口语、写作、模考主链路。
3. 训练、诊断、模考在应用中断后必须存在明确的恢复路径。
4. 同一账号在 Web 与移动端切换时，计划、进度、模考与账户状态保持一致。
5. 报告导出、账号导出、删除账号在移动端必须可执行并有结果反馈。
