# PRD: IELTS Self-Hosted Learning App

## 文档信息
- 版本: v2.9
- 状态: Active Baseline + Mobile Core Coverage
- 适用分支: `self-hosted`
- 目标形态: 自托管 Web 应用 + iOS/Android 原生移动客户端
- 当前已实现客户端: Web (`React + Vite`) + Mobile 首日学习链路、听力/阅读训练、实时口语、写作批改、模考报告与账户中心 (`React Native + Expo`)
- 移动端选型: 见 `docs/architecture/Mobile-Technology-Selection.md`
- 服务端技术: Fastify + WebSocket

## 1. 产品定位
这是一个面向 IELTS 备考场景的自托管学习应用，目标是提供一套完整的“诊断 -> 计划 -> 训练 -> 反馈 -> 模考 -> 复盘”闭环。

`self-hosted` 分支当前已经交付 Web 端学习主链路，并新增了一个移动端首日学习链路、听力/阅读训练、实时口语、写作、模考报告与账户中心基础能力。产品范围已经扩展为“同一套自托管后端同时服务 Web、iOS 与 Android 学习端”，移动端核心用户域已经覆盖当前 Web 主链路。

该分支不再承担商业化、后台运营、发布治理或供应商运行时编排职责，只保留学习主链路。

## 2. 核心目标
1. 让学习者可以从注册开始，在 Web 和 iOS/Android 客户端完成同一套完整备考闭环。
2. 让部署方可以用最少依赖把系统跑起来，默认支持纯内存模式，按需切换到 Postgres，并让 Web 与移动端共用同一套 API/WS 服务。
3. 让代码、文档和测试围绕同一套核心能力收敛，避免保留商业版和运维版残留，同时避免为移动端单独复制一套后端业务。

## 3. 范围定义
### 3.1 当前已实现范围
1. 用户注册、登录、刷新、退出
2. 入门目标设置、诊断问答、计划生成与调整历史
3. 学习进度同步与冲突查询
4. 听力、阅读训练
5. 错题重练队列、播放状态恢复、阅读计时器
6. 实时口语对练、发音反馈、同题重答与对比
7. 写作批改、模板插入、改写复评与历史档案
8. 全科模考、报告生成、报告导出与计划回写撤销
9. 行为分析事件上报、汇总查询与轻量 A/B 实验
10. 个性化提醒偏好、提醒推荐与点击追踪
11. 账号资料查询、数据导出、删除申请与删除执行
12. `apps/mobile` 已打通实例配置、安全 token 存储、注册/登录、首页工作台、入门目标、首次诊断、学习计划、学习进度、听力训练、阅读训练、实时口语、写作批改、模考与报告、账户中心、提醒偏好、未成年人监护留痕、未成年人专门学习时长控制、数据导出、删除账号，以及 API/WS 连接 smoke
13. `packages/shared-client` 已开始承接 Web 与 Mobile 共用的 API 客户端、类型和校验逻辑

### 3.2 已确认下一阶段范围
1. 开发 iOS 与 Android 学习端，面向手机设备交付原生安装包或商店分发形态。
2. 移动端功能范围以当前 Web 学习主链路为基线，覆盖注册、登录、入门目标、诊断、计划、进度、听力、阅读、实时口语、写作、模考、账户。
3. 移动端必须复用当前 Fastify API 与 WebSocket 契约，不引入独立移动端专用业务后端。
4. 移动端必须支持自托管部署方的实例接入，包括 API 与 WebSocket 地址配置、环境隔离和账号重新登录。
5. 移动端必须保留与 Web 一致的学习数据、计划、进度、模考、导出与删除语义。

### 3.3 Out Of Scope
1. 支付、订阅、会员、优惠券、家庭计划
2. Admin 后台、订单查询、权限校正、内容审核发布
3. 发布治理、灰度、稳定性演练、混沌测试、回滚控制台
4. Provider runtime 管理、支付 webhook runtime、system RBAC
5. 桌面原生客户端、平板专项版本、手表/TV 端、完全离线题库模式

## 4. 目标用户
1. 需要自托管 IELTS 练习环境的团队或个人
2. 希望演示或验证完整 IELTS 学习闭环的开发者
3. 需要在本地或私有环境中部署训练系统的实施方

## 5. 关键用户流程
### 5.1 新用户入门
1. 注册账号
2. 登录
3. 填写目标分数、考试日期、每周学习时长和薄弱项
4. 完成诊断问答
5. 获得能力估计与激活中的学习计划

### 5.2 日常训练
1. 查看首页和当前计划
2. 进入听力或阅读训练
3. 提交答案并获得结构化反馈
4. 将错题加入重练队列
5. 再次发起重练并观察熟练度变化

### 5.3 口语训练
1. 创建实时口语会话
2. 通过 WebSocket 进行对练
3. 查看会话摘要、事件流与发音反馈
4. 需要时发起同题重答并查看对比

### 5.4 写作训练
1. 选择 Task 1 或 Task 2
2. 提交作文获取评分
3. 使用模板插入辅助重写
4. 进行改写复评并保存档案

### 5.5 模考与复盘
1. 创建模考
2. 保存分科进度
3. 中断后恢复
4. 提交模考并生成报告
5. 把报告结果回写到学习计划
6. 必要时撤销一次回写

### 5.6 账号管理
1. 查看账户状态
2. 导出个人数据
3. 发起删除申请
4. 确认删除账号

## 6. 功能要求
### 6.1 多端一致性
1. Web、iOS、Android 必须共享同一套学习业务语义和服务端数据模型。
2. 移动端要求能力对齐，不要求逐像素复刻 Web 交互与布局。
3. 学习进度、计划状态、模考状态、账户状态必须支持跨端同步。

### 6.2 账号与会话
1. 支持邮箱或手机号注册。
2. 支持基于 refresh token 的会话续期。
3. 支持登录失败计数与失效控制。
4. 移动端必须使用安全存储保存 token，并在冷启动、热启动、前后台切换后恢复会话判断。
5. 用户退出登录、切换自托管实例或删除账号后，移动端必须清除本地敏感会话数据。

### 6.3 诊断与计划
1. 支持入门目标录入。
2. 支持按题提交诊断答案。
3. 支持暂停、恢复、完成诊断。
4. 支持查看当前生效计划和计划调整历史。
5. 移动端必须在应用被系统中断或切到后台后，能够恢复诊断与计划查询状态。

### 6.4 训练
1. 听力支持播放状态保存与恢复。
2. 阅读支持 `training` / `exam` 两种模式与计时器恢复。
3. 训练结果可进入重练队列。
4. 移动端必须在音频权限、耳机切换、前后台切换、弱网重连等场景下保持可恢复的训练状态。

### 6.5 口语
1. 支持标准口语和 `role-play` 两类会话。
2. 支持 `part` 切换、结束、重答和对比。
3. 支持发音反馈任务追踪。
4. 支持会话恢复窗口。
5. 移动端必须处理麦克风权限、系统来电或录音中断、网络波动后的重连与状态提示。

### 6.6 写作
1. 支持评分、证据句、建议项输出。
2. 支持模板插入与采纳率统计。
3. 支持改写后再评分和历史归档。
4. 移动端必须支持长文本输入、草稿保留和档案查看。

### 6.7 模考
1. 支持全科模考实例创建。
2. 支持进度保存与恢复。
3. 支持报告导出与计划回写。
4. 移动端必须支持在设备内打开或分享导出结果。

### 6.8 学习支撑能力
1. 支持分析事件批量写入。
2. 支持汇总查询。
3. 支持提醒推荐与点击反馈。
4. 支持轻量 A/B 实验配置与分流。
5. 分析事件必须区分 `web`、`ios`、`android` 平台维度。

### 6.9 自托管配置
1. 移动端必须支持部署方以构建时默认值或运行时配置的方式指定 API 与 WebSocket 地址。
2. 若用户切换实例地址，应用必须重新建立环境边界，不得与旧实例共享 token 或缓存。
3. 核心学习链路不得依赖强绑定的第三方托管后端。

## 7. 非功能要求
1. 默认可在纯内存模式运行，便于开发和快速演示。
2. 各学习域支持独立切换到 Postgres。
3. 服务端必须暴露 `/health`。
4. 账号密钥必须通过 `AUTH_SECRET` 或 `AUTH_SECRET_FILE` 提供。
5. 主链路自动化测试必须持续通过。
6. 移动端实现后，关键状态恢复场景必须覆盖自动化或脚本化 smoke。
7. 移动端本地缓存不得成为唯一数据源，服务端状态仍是最终事实源。

## 8. 阶段口径
1. 截至 2026-03-28，`self-hosted` 分支当前已实现形态是“Web 客户端 + Fastify API/WS 服务端 + Mobile 学习基础能力”。
2. 当前 `apps/mobile` 已落实例配置、安全会话存储、注册/登录、首页工作台、入门目标、首次诊断、学习计划、学习进度、听力训练、阅读训练、实时口语、写作批改、模考与报告、账户中心、提醒偏好、未成年人监护留痕、未成年人专门学习时长控制、数据导出、删除账号，以及 API/WS smoke 和 route-level vitest smoke；当前 Web 主链路与账户主链路都已建立移动端入口。
3. 移动端完整范围见 `docs/PRD-Appendix-Mobile-Client.md`，技术决策见 `docs/architecture/Mobile-Technology-Selection.md`。

## 9. 验收标准
1. 现有 Web 基线继续满足 `npm run typecheck` 与 `npm test`。
2. 在最小内存模式下，Web 端可继续完成注册、诊断、训练、模考、导出。
3. 在 Postgres 模式下，Web 端可继续完成认证、学习主链路与模考恢复 smoke。
4. 移动端进入实现阶段后，iOS 与 Android 必须各自通过注册、诊断、计划、训练、口语、写作、模考、导出、账户删除的端到端验收。
5. 同一账号在 Web 与移动端之间切换时，计划、进度、模考与账户状态必须保持一致。

## 10. 明确约束
1. 不再接受“恢复支付或后台能力”的隐式需求进入该分支。
2. 所有新增文档必须以当前 self-hosted 服务端边界为准，不得把移动端需求写成独立 SaaS 产品。
3. 移动端建设优先复用既有 TypeScript 契约与 API 语义，不默认走双端完全独立实现。
4. 若历史材料与本 PRD 冲突，以本 PRD 为准；若本 PRD 与当前代码实现存在阶段差异，以“当前已实现范围”和“阶段口径”解释。
