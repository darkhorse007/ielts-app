# PRD: IELTS AI 跨平台提分 App（中国大陆）

## 文档信息
- 文档版本: v1.0
- 状态: Draft for Build
- 创建日期: 2026-02-25
- 目标发布窗口: 2026 Q3
- 适用平台: iOS, Android, Windows, macOS
- 语言策略: 界面简体中文为主，学习内容中英混合

## 1. 产品概述
本产品是一款以“雅思考试过关”为核心目标的跨平台学习 App，面向中国大陆考生，围绕雅思考试标准构建听、说、读、写闭环训练。产品提供即时反馈的虚拟对练教练，并内置可编排的 AI Agent 系统，支持接入第三方商业 LLM。

## 2. 业务目标与成功标准
### 2.1 北极星目标
提升用户在 8 周学习周期内从总分 5.5 达到 6.5 的通过率。

### 2.2 业务目标
1. 建立“诊断 -> 计划 -> 训练 -> 反馈 -> 复盘 -> 再计划”的可复用学习闭环。
2. 通过即时 AI 反馈缩短纠错周期，提升有效学习时长占比。
3. 通过订阅制实现可持续商业化。

### 2.3 指标目标（首个完整版本上线后 90 天）
1. D7 留存率 >= 28%。
2. 免费试用转订阅率 >= 9%。
3. 周学习任务完成率 >= 55%。
4. 完成至少 2 次模考用户的平均总分提升 >= 0.5 分。
5. AI 反馈满意度 >= 4.3/5.0。

## 3. 目标用户与场景
### 3.1 目标人群
1. 中国大陆雅思考生。
2. 目标分段 5.5 -> 6.5。
3. 备考周期 1-6 个月。

### 3.2 用户画像
1. 在校生: 时间相对碎片化，预算敏感。
2. 职场人: 学习时间集中在晚间，追求效率与明确路径。
3. 二战考生: 对薄弱项有明确认知，希望高强度纠偏。

### 3.3 关键使用场景
1. 通勤期间进行口语对练与词汇纠偏。
2. 晚间完成听读写专项训练。
3. 周末进行全真模考并复盘。
4. 考前两周执行冲刺计划。

## 4. 产品定位与价值主张
### 4.1 产品定位
AI 驱动的雅思过关训练助手，不以泛英语学习为主，而以考试提分为第一目标。

### 4.2 核心价值
1. 对准考纲: 任务、题型、评分维度与雅思标准对齐。
2. 即时反馈: 训练后秒级给出结构化纠偏建议。
3. 个性化计划: 随学习数据持续更新周计划。
4. 跨端一致: 手机和桌面端学习进度实时同步。

### 4.3 竞品基线与差异化策略（2026-02）
基于 `docs/market/Competitive-Analysis-IELTS-2026.md` 的公开市场调研：
1. 市场现实: 雅思备考商业软件已高度成熟，本产品不以“是否存在竞品”为假设，而以“是否能更快提分”为核心竞争点。
2. 基线能力（必须达标）:
   - 四科训练 + 模考 + 错题复盘 + 订阅权益闭环；
   - 移动端优先体验和稳定 AI 反馈。
3. 重点差异化（必须超越）:
   - 真跨平台一致体验（iOS/Android/Windows/macOS）；
   - 证据化即时反馈（片段定位、可改写建议、前后对比）；
   - 多 LLM 可插拔与自动回退；
   - 后台运营闭环（内容发布、权益校正、审计追踪）。
4. 成功判据:
   - 相比“题库刷题型”竞品，8 周周期内用户任务完成率与分项提分幅度具备可观测优势。

## 5. 范围定义
### 5.1 In Scope（标准商业版）
1. 账号体系与跨端同步。
2. 入门诊断与动态学习计划。
3. 听力、口语、阅读、写作四科训练。
4. 全真计时模考与复盘报告。
5. AI 虚拟对练教练与多 Agent 编排。
6. 订阅、试用与权益管理。
7. 数据分析埋点与运营看板基础能力。
8. 后台管理系统（运营、内容、订单与风控最小闭环）。

### 5.2 Out of Scope（本期不做）
1. 真人外教 marketplace。
2. 面向外部机构的 B2B 机构/学校管理后台。
3. 线下课程排课与交易能力。

## 6. 核心用户流程
1. 用户注册并完成目标设置（目标分、考试日期、可学习时长）。
2. 系统发起诊断测评并生成能力基线。
3. 生成 8 周学习计划和每日任务。
4. 用户完成专项训练并获得即时反馈。
5. 每周进行一次阶段测评，每两周完成一次模考。
6. Agent 更新学习计划并推送下周任务。
7. 用户查看趋势报告并执行冲刺策略。

## 7. 功能需求详述
### 7.1 账号与身份（P0）
1. 支持手机号、邮箱、第三方登录（Apple/Google/微信其一按地区策略接入）。
2. 支持多设备登录，后登录设备不强制挤出前设备。
3. 支持学习数据云端同步与加密存储。

验收标准:
1. 新用户注册到首个任务启动 <= 120 秒。
2. 同一账号在 2 台设备切换后进度差异 <= 5 秒延迟。

### 7.2 诊断测评与学习计划（P0）
1. 首次诊断覆盖听说读写最小题量包。
2. 输出分项能力估计、薄弱点、建议学习路径。
3. 生成 8 周计划，支持每周滚动更新。
4. 计划可根据错题再错率和模考成绩自动调整。

验收标准:
1. 首次诊断完成时长 <= 5 分钟。
2. 计划更新在新数据产生后 2 分钟内生效。

### 7.3 听力训练（P0）
1. 题型覆盖: 选择、填空、匹配、地图。
2. 支持倍速播放、句段回放、错题重听。
3. 错因标签: 定位错误、同义替换误判、信息遗漏、干扰项误选。

验收标准:
1. 每题反馈包含错因标签和改进动作。
2. 错题支持一键进入“重练队列”。

### 7.4 口语训练与虚拟对练教练（P0）
1. 覆盖 Part 1/2/3。
2. 支持实时追问与上下文连续对话。
3. 输出评分维度: Fluency, Lexical Resource, Grammar, Pronunciation。
4. 输出结构化反馈: 问题片段、可替换表达、二次作答建议。
5. 支持“再答一次”即时纠偏模式。

验收标准:
1. 语音结束后 3 秒内开始返回反馈首条内容。
2. 每轮反馈必须包含 4 个评分维度和至少 2 条可执行改进建议。

### 7.5 阅读训练（P0）
1. 题型覆盖: T/F/NG、段落匹配、标题匹配、摘要填空。
2. 输出定位路径与错因分析。
3. 提供限时训练模式与考试模式。

验收标准:
1. 每道错题显示定位依据或逻辑依据。
2. 阶段复盘可按题型输出正确率趋势。

### 7.6 写作训练（P0）
1. 支持 Task 1 和 Task 2。
2. 按 TR/CC/LR/GRA 四维评分并给出解释。
3. 输出结构建议、逻辑漏洞、表达替换建议。
4. 支持“改写并复评”闭环。

验收标准:
1. 单篇反馈生成时间 <= 90 秒。
2. 反馈必须包含分项评分、证据句、至少 3 条修改建议。

### 7.7 模考与复盘（P0）
1. 提供全真计时模考流程。
2. 支持断点续考，异常退出可恢复。
3. 模考结束后输出总分估计、分项趋势、错因分布、下周行动建议。

验收标准:
1. 模考结束后 2 分钟内生成报告。
2. 报告可直接转化为下周任务包。

### 7.8 学习系统（P0）
1. 每日任务卡、学习时长统计、连续打卡。
2. 错题本与重练计划自动生成。
3. 考试倒计时与冲刺提醒。

验收标准:
1. 每日任务含目标时长、完成标准、反馈入口。
2. 错题重练后自动更新熟练度状态。

### 7.9 订阅与支付（P0）
1. 免费试用: 每日有限 AI 调用额度 + 基础题库。
2. 订阅权益: 高级题库、深度反馈、全科模考、无限重练。
3. 支持自动续费、取消续费、权益降级。

验收标准:
1. 到期和降级策略生效延迟 <= 1 分钟。
2. 订阅与试用权益在各端一致。

### 7.10 运营与通知（P1）
1. 学习提醒、模考提醒、周报推送。
2. A/B 实验开关支持文案与任务排序策略。
3. 用户反馈收集入口。

### 7.11 后台管理系统（P0）
1. 后台账号与权限管理: 支持 Admin 登录、RBAC 角色（运营/内容/客服/财务只读）。
2. 用户管理: 支持用户检索、账号冻结/解冻、注销状态查看。
3. 订阅与订单管理: 支持订单检索、支付状态核查、权益人工校正。
4. 内容管理: 支持题库内容上架/下架、版本状态切换、发布记录。
5. 操作审计: 所有高风险操作记录 `operator/action/resource/timestamp`。

验收标准:
1. 不同角色仅可访问授权菜单与操作，越权请求返回 `403`。
2. 用户冻结/解冻状态在 1 分钟内全端生效。
3. 权益人工校正流程可追踪且可回滚一次。
4. 内容发布记录可追溯到操作人和版本号。

## 8. AI 与 Agent 系统需求
### 8.1 Agent 角色定义
1. Coach Agent: 对练、追问、反馈生成。
2. Evaluator Agent: 结构化评分与证据提取。
3. Planner Agent: 学习计划生成与动态调整。
4. Guardrail Agent: 安全策略、合规过滤、输出约束。

### 8.2 多 LLM 可插拔策略
1. 通过统一 Provider Adapter 抽象接入第三方商业 LLM。
2. 路由策略按任务类型、时延、成本、可用性动态选择模型。
3. 主模型失败时自动回退到备模型。
4. Provider 切换不影响上层业务接口与数据结构。

### 8.3 反馈质量要求
1. 输出必须可执行，避免泛化建议。
2. 关键建议必须附证据句或对应答题片段。
3. 对于不确定结论，必须标注置信度或给出保守建议。

## 9. 平台与技术架构要求
### 9.1 客户端
1. 使用 Flutter 统一构建 iOS/Android/Windows/macOS。
2. UI 组件支持响应式布局与桌面快捷交互。
3. 语音会话支持前后台切换恢复。

### 9.2 服务端
1. API Gateway + 业务服务 + AI Orchestrator 分层。
2. 学习数据、会话数据、订阅数据分域管理。
3. 关键链路支持熔断、重试、限流与可观测性。

### 9.3 同步策略
1. 会话与学习进度采用增量同步。
2. 断网时本地缓存，联网后自动补传。

### 9.4 后台管理端
1. 后台采用 Web 管理端（PC 浏览器优先）。
2. 管理接口统一使用 `/v1/admin/*` 前缀并要求角色鉴权。
3. 高风险操作（冻结、权益校正、内容发布）必须写审计日志。

## 10. 非功能需求
### 10.1 性能
1. 常规 API P95 响应 <= 1.5 秒。
2. AI 反馈首 token 延迟 <= 3 秒。
3. 关键页面冷启动 <= 2.5 秒（中端设备）。

### 10.2 稳定性
1. 客户端崩溃率 <= 0.3%。
2. 核心服务可用性 >= 99.9%。
3. AI 路由失败自动回退成功率 >= 99%。

### 10.3 安全与隐私
1. 传输全链路 TLS。
2. 敏感数据加密存储。
3. 提供账号注销与数据删除流程。

## 11. 合规与版权要求
1. 题库内容需具备版权授权，不得直接搬运受版权保护真题原文与音频。
2. 用户协议与隐私政策明确 AI 生成内容边界。
3. 涉及未成年人时展示监护与时长提醒。
4. 日志采集遵循最小化原则，默认脱敏。

## 12. 商业模式
1. 免费层: 基础题库、限额 AI 反馈、基础进度统计。
2. 订阅层（月/季/年）: 全题库、深度反馈、模考、高级复盘、冲刺计划。
3. 促活策略: 新用户 7 天试用、阶段性挑战任务、周报激励。

## 13. 里程碑与发布计划
### M1（第 1-4 周）
1. 账号体系、基础题库框架、诊断流程、听读训练最小闭环、口语 MVP。

### M2（第 5-8 周）
1. 写作批改、模考系统、学习计划动态更新、订阅与权益体系、后台管理 MVP。

### M3（第 9-12 周）
1. 多 LLM 路由、全链路监控、性能优化、后台权限与审计增强、商店发布准备。

## 14. 主要风险与应对
1. 评分可信度风险: 建立人工标注集，持续校准模型评分偏差。
2. 成本风险: 引入模型路由与缓存策略，按任务分级调用。
3. 合规风险: 上线前进行版权与隐私合规审计。
4. 跨端一致性风险: 建立统一组件规范和自动化回归矩阵。
5. 后台误操作风险: 对高风险操作启用 RBAC、审计与可回滚机制。

## 15. 验收总标准
1. 用户可在单次会话中完成“训练 -> 反馈 -> 再练”闭环。
2. 四科均有可量化评分与可执行建议。
3. 四端功能一致并通过核心路径验收。
4. 订阅、权限、数据同步、风控策略稳定运行。
5. 质量与性能指标达到本 PRD 定义阈值。
6. 后台管理核心能力（用户、订单、内容、审计）通过 P0 验收。

## 16. 默认决策与假设
1. 范围默认采用“标准商业版”，不扩展到机构版。
2. 目标分段默认 5.5 -> 6.5。
3. 技术路线默认 Flutter 四端统一。
4. AI 默认多 Provider 可插拔，至少支持 2 个商业 LLM Provider。
5. 计费默认订阅制 + 免费试用。
6. 首发包含最小后台管理系统，优先覆盖运营与风控闭环。
6. 若与后续法务要求冲突，以法务合规版本为准并回写本 PRD。
