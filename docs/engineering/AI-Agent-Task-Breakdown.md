# AI Agent Task Breakdown（P0 首发）

## 1. 目标
将 AI 能力拆解为可执行任务包，支撑口语对练、写作批改、学习计划更新，并满足多 LLM 可插拔与故障回退要求。

## 2. 目标能力边界
1. 支持 `Coach Agent`, `Evaluator Agent`, `Planner Agent`, `Guardrail Agent`。
2. 支持至少 2 个商业 LLM Provider 接入。
3. 支持主路由失败自动回退到备路由。
4. 关键链路可观测并可回放问题会话。

## 3. 架构分层
1. Agent Orchestrator 层: 负责任务编排与上下文管理。
2. Provider Adapter 层: 屏蔽不同 LLM API 差异。
3. Policy Guard 层: 负责安全规则与输出约束。
4. Evaluation 层: 质量评测、离线评测集与线上指标。

## 5. 任务包详细定义
### AI-001 Orchestrator 基础框架
1. 实施内容:
- 定义任务类型: `speaking_coach`, `writing_score`, `plan_update`。
- 统一上下文结构: 用户目标、历史会话、配额、设备信息。
- 支持同步任务与异步任务编排。
2. 验收标准:
- 所有 AI 调用经由 Orchestrator 入口。
- 失败链路可携带 `trace_id` 回溯。

### AI-002 Provider Adapter 标准化
1. 实施内容:
- 实现统一接口: `generateText`, `generateSpeechFeedback`, `scoreWriting`, `healthCheck`。
- 接入 Provider-A（主）与 Provider-B（备）。
- 处理速率限制、重试和超时。
2. 验收标准:
- 同一请求在不同 Provider 返回结构一致。
- Provider 超时可在 10 秒内判定并触发回退。

### AI-003 Prompt 与输出 Schema 契约
1. 实施内容:
- 为口语、写作、计划更新建立 Prompt 模板版本库。
- 定义输出 JSON Schema 并在服务端强校验。
- 支持模板灰度发布。
2. 验收标准:
- 不合规输出被拦截并触发重试。
- 输出字段缺失率 <= 1%。

### AI-004 Guardrail 策略引擎
1. 实施内容:
- 输入侧: 敏感内容识别、注入攻击检测。
- 输出侧: 不当内容过滤、事实性表达约束。
- 审计日志记录拦截原因。
2. 验收标准:
- 高风险输入被拦截率 >= 99%（基于内部对抗集）。
- 误杀率 <= 3%。

### AI-005 Fallback Router 策略
1. 实施内容:
- 规则输入: 任务类型、Provider 健康、成本策略。
- 切换策略: 超时、错误率、预算上限触发切换。
- 记录切换事件用于成本与稳定性分析。
2. 验收标准:
- 回退触发后总体成功率 >= 99%。
- 回退前后接口响应结构保持一致。

### AI-006 口语 Coach 流水线
1. 实施内容:
- 构建口语任务链: ASR -> 对话追问 -> 评分 -> 反馈聚合。
- 输出 Fluency/Lexical/Grammar/Pronunciation 四维评分。
- 生成“再答一次”改进任务。
2. 验收标准:
- 首条反馈 <= 3 秒（P95）。
- 每轮至少 2 条可执行建议且包含证据片段。

### AI-007 写作 Evaluator 流水线
1. 实施内容:
- 支持 Task 1/Task 2。
- 输出 TR/CC/LR/GRA 四维评分与解释。
- 提供证据句与改写建议。
2. 验收标准:
- 单篇反馈 <= 90 秒（P95）。
- 输出包含评分、证据和至少 3 条建议。

### AI-008 Planner 计划更新 Agent
1. 实施内容:
- 读取模考报告与近期训练结果。
- 更新下一周学习任务与时长分配。
- 输出变更原因与影响说明。
2. 验收标准:
- 新结果产生后 2 分钟内完成计划更新。
- 每次更新含可读理由并可审计。

### AI-009 AI 可观测与告警
1. 实施内容:
- 监控指标: 成功率、延迟、回退率、空反馈率、字段缺失率。
- 面板维度: `task_type`, `provider`, `platform`, `version`。
- 告警策略: 高回退率、高延迟、质量下降。
2. 验收标准:
- 告警能在 5 分钟内触发并通知值班。
- 异常会话可一键定位到 `agent_run_id`。

### AI-010 评测集与上线门禁
1. 实施内容:
- 建立口语/写作离线评测集。
- 设立发布门禁阈值并纳入 CI。
- 回归报告产出模板化。
2. 验收标准:
- 发布前必须通过离线评测阈值。
- 未达阈值版本禁止进入灰度。

## 6. 依赖关系
1. AI-001 先于 AI-002/AI-003/AI-005。
2. AI-003 与 AI-004 完成后，AI-006/AI-007 才可进入联调。
3. AI-006/AI-007 是 AI-008 的输入前提。
4. AI-009/AI-010 在 S6 前必须完成，否则不满足发布门禁。

## 7. 角色分工建议
1. AI 工程:
- 负责 AI-001~AI-008 核心实现。
2. 后端工程:
- 负责接口接入、存储、日志、配额联动。
3. 客户端工程:
- 负责实时会话接入、反馈渲染和重试策略。
4. QA:
- 负责 AI 功能回归、质量评测、对抗测试。

## 8. 风险与缓解
1. 风险: 模型漂移导致评分不稳定。
- 缓解: 周期性重跑评测集，监控评分分布漂移。
2. 风险: 高峰期延迟飙升。
- 缓解: Provider 多路由 + 降级策略 + 排队保护。
3. 风险: Prompt 注入攻击。
- 缓解: Guardrail 输入清洗 + 输出校验 + 黑名单策略。

## 9. 完成定义（DoD）
1. 任务代码合并并通过契约测试。
2. 监控指标接入并有告警规则。
3. 关键场景通过 QA 验收。
4. 文档和运行手册同步更新。
